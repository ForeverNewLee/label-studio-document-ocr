# 英文票据OCR实体标注服务需求文档

## 1. 项目概述

### 1.1 项目目标
构建一个基于Label Studio的数据标注服务，用于处理2万张英文票据图片的OCR结果，进行敏感实体识别和类别标注，以支持数据脱敏和隐私保护模型训练。

### 1.2 业务背景
- **数据来源**: 2万张英文票据图片
- **预处理状态**: 已通过OCR处理并生成包含掩码标记的文本
- **标注需求**: 识别和标注文档中的所有敏感实体（包括已被`[MASK]`遮挡的和未遮挡的），进行精确分类
- **应用场景**: 数据脱敏模型训练、敏感信息识别、隐私保护

## 2. 功能需求

### 2.1 核心功能
1. **批量任务导入**: 支持2万个标注任务的批量导入
2. **敏感实体标注**: 识别并标注文档中的所有敏感实体（无论是否被MASK）
3. **类别分类**: 为识别的敏感实体分配正确的类别标签
4. **结果导出**: 按指定格式导出标注结果

### 2.2 标注工作流程
```
标注指令解读 → 文档分析 → 敏感实体识别 → 类别分配 → 实体清单构建 → 结果验证 → 提交标注
```

### 2.3 任务输入格式
每个标注任务包含：
- **标注指令**: 找出文档中的敏感实体并进行分类标注
- **实体类别定义**: 4大类敏感信息的详细说明
- **OCR文本**: 包含`[MASK]`标记的预处理文本
- **期望输出**: 实体清单格式示例

### 2.4 标注任务说明
标注员需要：
1. 识别文档中所有敏感实体（包括被`[MASK]`遮挡的内容）
2. 对每个敏感实体进行精确的类别分类
3. 构建完整的实体清单，格式为"实体文本: 类别标签"

## 3. 实体类别体系

### 3.1 主要类别 (4大类)
1. **人名相关**: 人名、人名缩写、姓、名
2. **地址相关**: 地址、街道名、街道号、邮编、国家、美国的州、城市  
3. **证件号码**: 护照号、身份证号、驾照号、银行账号、卡号、发票号
4. **时间和联系信息**: 时间戳、出生日期、IP地址、硬件地址

### 3.2 具体标签映射
| 实体类型 | 标签代码 | 示例 |
|---------|---------|------|
| 完整姓名 | FullName | Heather Hatfield, LADISLADA ANDRADE |
| 名 | FirstName | Heather, LADISLADA |
| 姓 | LastName | Hatfield, ANDRADE |
| 完整地址 | Address | 36441 Phillips Underpass Suite 106, 443 DOUBLE TREE |
| 街道号 | StreetNumber | 36441, 443 |
| 街道名 | StreetName | Phillips Underpass, DOUBLE TREE |
| 城市 | City | New Daniel, LUFKIN |
| 州 | State | MT, TX |
| 邮编 | ZipCode | 49458, 75904 |
| 日期 | Date | 05/06/2022, 12/06/2019 |
| 发票号 | InvoiceNumber | T96087065 |
| 公司名称 | CompanyName | Wilson, Taylor and Kim and Sons |
| 军事地址 | MilitaryAddress | USNS Palmer, FPO AE 79899 |

### 3.3 扩展类别
根据实际标注过程中遇到的实体类型，已扩展到以下标签：
- CompanyName: 公司/组织名称
- InvoiceNumber: 发票/单据编号
- MilitaryAddress: 军事邮政地址
- Amount: 金额信息（如需要保护的财务数据）

### 3.4 标注策略说明
**关键发现**: 基于demo分析，实际标注任务与初始理解存在差异：

1. **标注对象**: 需要标注的是文档中的**所有敏感实体**，包括：
   - 已被`[MASK]`遮挡的敏感信息
   - 未被遮挡但属于敏感类别的信息

2. **任务本质**: 这是一个**敏感信息识别和分类**任务，目标是：
   - 训练数据脱敏模型
   - 建立敏感信息检测能力
   - 完善隐私保护机制

3. **标注重点**: 
   - 重点关注个人身份信息（PII）
   - 地址和联系方式信息
   - 时间相关的隐私信息
   - 证件和账号类信息

4. **质量要求**:
   - 准确识别所有被MASK的实体类型
   - 发现文档中其他潜在的敏感信息
   - 确保类别标注的一致性和准确性

## 4. 技术需求

### 4.1 标注界面要求
- **双栏布局**: 左侧显示标注指令，右侧显示待标注文本
- **实体高亮**: 支持文本选择和高亮显示
- **类别选择**: 便捷的类别选择器
- **进度跟踪**: 显示当前任务进度和完成状态

### 4.2 数据处理要求
- **任务分配**: 支持多标注员并行工作
- **质量控制**: 支持标注结果审核和校验
- **结果统计**: 提供标注进度和质量统计

### 4.3 输出格式要求
```
实体文本: 类别标签
Heather Hatfield: FullName
Heather: FirstName
Hatfield: LastName
36441 Phillips Underpass Suite 106: Address
New Daniel: City
MT: State
49458: ZipCode
05/06/2022: Date
```

## 5. 非功能性需求

### 5.1 易用性要求
- **学习成本**: 新标注员能够快速掌握操作
- **操作便捷**: 快捷键支持，提高标注效率
- **错误处理**: 友好的错误提示和恢复机制

## 9. 风险识别

### 9.1 技术风险
- Label Studio定制化复杂度超预期
- 大数据量导致的性能问题
- 实体类别定义存在歧义

### 9.2 业务风险
- 标注质量不达标，需要重新标注
- 标注员流失，影响进度
- OCR预处理质量影响标注效果

### 9.3 风险应对
- 技术预研和原型验证
- 建立标注质量控制机制
- 制定详细的标注规范和培训材料
